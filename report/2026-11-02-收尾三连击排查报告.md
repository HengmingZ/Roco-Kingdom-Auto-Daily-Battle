# 连招收尾三连击问题排查与修复报告

日期：2026-11-02
范围：`Skill-Locator/inference/clicker.py`、`Skill-Locator/gui/combo_tab.py`、`Skill-Locator/tests/`

## 1. 问题现象

自动连招每轮结束后的"屏幕中心三连击"在游戏中无效果（界面不跳转），而手动点击同一位置有效。

## 2. 排查过程与结论

| 假设 | 验证方式 | 结论 |
|---|---|---|
| 点击坐标写死/不在选中屏幕 | 代码审查 | 排除。坐标取自 GUI 选中的 `current_monitor` 中心 |
| 多显示器归一化错误 | 改虚拟屏归一化后实机测试 | **误改，已回退**。Interception 驱动的绝对坐标只映射主屏，原实现正确 |
| 按压时长/击间间隔不足 | 增加 hold 0.3s、间隔 0.5s | 排除，单独测试仍失败 |
| 驱动未安装或注入失效 | 相对移动实测 + tk 按钮点击实测 | 排除。驱动级移动/点击在 OS 层均送达 |
| 注入事件特征被游戏丢弃 | 对照原项目 RocoKingdom_Clicker 管道实测 | **确认根因** |

**根因**：原点击管道与游戏接受的参考管道有三处差异——

1. 向全部 10 个鼠标设备群发事件（参考实现只发设备 11）
2. 叠加了带 `LLMHF_INJECTED` 标记的 `mouse_event`（反作弊会因此丢弃整个点击手势）
3. 多发了一次驱动级绝对移动

## 3. 已实施的修复

- `clicker.py`：`hold_click_at` 重写为参考管道（单设备、纯 interception 事件、仅 `SetCursorPos` 定位），新增 `InterceptionEngine.send_stroke_to`；技能点击 `click_at` 保持不变。
- `combo_tab.py`：收尾三连击使用 `hold_click_at`（按住 0.3s、击间 0.5s），失败时状态栏告警；收尾各阶段（滚轮/按 1/空格/15s 倒计时/三连击）进度实时显示。
- 测试工具：`tests/test_triple_click.py`（三连击单独模拟，支持 `--here`/`--ref`/`--hold`），`tests/test_clicker_interception.py` 实机通过。

**验证结果**：参考管道在游戏结算界面实测点击成功（界面跳转）；新管道 OS 层测试通过。游戏内整轮连招效果待实测。

## 4. 进行中：OCR 定位"再次挑战"

固定坐标依赖"按钮在屏幕中心"的假设，不稳健。已引入 `rapidocr-onnxruntime`（中文模型自带，CPU 可用）：

- 新增 `inference/retry_locator.py`：整屏 OCR，按文字"再次挑战"定位按钮中心（含容错匹配）。
- 新增 `tests/test_retry_locator.py`：输出全部识别文字并保存标注截图，用于验证游戏字体识别质量。

**待办**：在真实结算页运行定位测试 → 验证通过后将 OCR 定位接入连招收尾（轮询出现即点，取代固定 15s 等待），识别失败再回退屏幕中心三连击；若识别不准则调整匹配规则。
