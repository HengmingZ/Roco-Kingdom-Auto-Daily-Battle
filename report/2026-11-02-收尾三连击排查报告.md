# 连招收尾三连击问题排查与修复报告

日期：2026-11-02
范围：`Skill-Locator/inference/clicker.py`、`Skill-Locator/gui/combo_tab.py`、`Skill-Locator/inference/retry_locator.py`、`Skill-Locator/tests/`

## 1. 问题现象

自动连招每轮结束后的收尾操作（屏幕中心三连击、点击"再次挑战"）在游戏中无效果，界面不跳转；手动点击有效。

## 2. 最终根因（两个叠加问题）

1. **`SetCursorPos` 在游戏前台时被反作弊（ACE）静默拦截**（返回失败、不设错误码）。改写为"纯净参考管道"时只保留了 `SetCursorPos` 定位，导致光标从未到达目标，点击全部落在物理鼠标位置。tk 测试一度"通过"是因为当时游戏未在前台遮挡测试窗口，具有误导性。
2. **多余的注入事件特征**：向 10 个鼠标设备群发 + 叠加带 `LLMHF_INJECTED` 标记的 `mouse_event`，在游戏的结算/按钮界面会被丢弃。

## 3. 已实施的修复

`clicker.py` 的 `hold_click_at` 最终形态：

- **驱动级绝对移动**定位（主屏目标；游戏前台也有效，且产生 raw input，游戏内光标能悬停按钮），移动后 `GetCursorPos` 校验、不到位重试一次
- **单设备（11）**按下 0.3s → 抬起，纯 interception 事件，无 `mouse_event`
- 无驱动时返回 False（连招页会在状态栏告警）
- 技能点击 `click_at` 未改动

`combo_tab.py` 收尾流程（`_post_round_actions`）：

1/5 滚轮上滚 → 2/5 按 1 → 3/5 按空格 → 4/5 (15s) 屏幕中心三连击（按住 0.3s、间隔 0.5s）→ 5/5 OCR 轮询识别"再次挑战"（最多 10s，最多点 3 次，消失即成功）→ 成功后等待 6s 再进入下一轮。全程进度栏实时显示，ESC 可随时停止。

OCR 方案：`rapidocr-onnxruntime`（中文模型随包分发，CPU 可用），`retry_locator.py` 整屏识别并按文字"再次挑战"定位按钮中心（实测置信度 1.00）。

## 4. 验证记录

- 驱动级移动/点击在游戏前台均可用（实机验证光标跳转、页面跳转）
- OCR 定位测试 `tests/test_retry_locator.py`：识别 10 个文本框，"再次挑战"得分 1.00，坐标 (1462, 1351)
- 端到端测试 `tests/test_ocr_clicker.py`：识别 → 点击 → 页面跳转成功
